# Organizer rules and final scorecard

Page numbers are the printed numbers in the Participant Guide.

## Six deliverables (p.14)
1. A complete, fully working digital solution, ready for real use.
2. Source code: public GitHub repository with the code and publishable files, run documentation, no sensitive data or secrets.
3. Explainer video, 2 minutes maximum.
4. PDF or PowerPoint deck: problem, solution, how it works, added value, technologies, results, continuation plan.
5. Documentation of the sharia and knowledge content and sources, how they are used and verified.
6. Live demo link, fully working and open for testing and review.

## Repository and link rules (p.32)
- Live demo link that lets the jury try the solution; test the link and every function before submitting.
- Repository on GitHub set to **Public**; a private repository is not accepted.
- Full code the team has the right to publish, with component licences and owners' rights.
- Runtime files allowed for publication, with no beneficiary data, passwords or secret keys.
- Documentation of the idea, setup, running and credits, with a register of sources, tools and licences.

## Final review before submission (p.33)
Code organized for jury review · no technical errors that block running · video ≤ 2 minutes · submit via the portal and keep the confirmation email; if the portal fails, email info@IslamicAIch.org with proof of the attempt and the participation number.

## Prior work (p.43)
Allowed with the starting version documented and rights disclosed; only work done 4–6 Oct is scored. A prototype alone is not enough: an integrated product, public GitHub repo, video up to 2 minutes and a deck are required.

## Track 03 success criterion (p.10)
Did the solution, when tested with the target group, improve understanding of an Islamic concept, or the fit and sequencing of the content and the continuity of the learner's journey — while respecting privacy and not inferring or classifying the user's religious or sensitive traits without a legitimate basis?

## Final judging (p.37; rubrics p.38–41) — screening score is not carried over
| Criterion | Weight | Level 5 asks for | MIZAN evidence (Runbook §1) |
|---|---|---|---|
| Technical quality and use of AI | 25% | Stable, repeatable results; documented method and limits; improvement attributable to AI | Stations live and stable; architecture doc; measured comparison vs static audio story; 3 runs |
| Benefit vs track success criterion | 20% | Improvement repeated across varied in-scope cases; results and limits documented | Crossover pilot, pre/post narration scores 0–3, limits stated |
| Reliability and scientific integrity | 15% | Consistent on the full test set over repeated runs; exposes its own limits and errors | 50 × 3 suite; public eval page; texts by platform ID; closed library; verbatim validator; review log |
| Innovation and added value | 15% | Test proves superiority over a specific alternative, with limits of the comparison | Measured vs static audio story; positioning vs memorization apps, Rayan & Bayan, general chatbots |
| User experience, communication, accessibility | 10% | Testing with the target group supports ease of use; improvements made from results | Tap-first, RTL, large targets, real recitation; ≥ 2 pilot-driven changes |
| Operational realism | 10% | Estimates backed by measurement; alternative for a critical dependency; practical adoption plan | Cost per session from logs; second LLM provider; partnership-first plan |
| Clarity of presentation and verifiability | 5% | Concise, easy to re-test, separates built from proposed | Built/Roadmap labels; judge quick-start in README and deck |

## Final round
Up to 20 finalists; Zoom session: 5 minutes demo + 3 minutes questions (p.43). Finalists announced 18 Oct; session 19–22 Oct (Runbook Phase 5).
